# Phase 4 — Content Studio / LinkedIn Radar: Scope Brainstorm

> **Status:** Draft for user review. Do NOT implement until reviewed.
> **Date:** 2026-05-22

---

## Q1: Audience — who is generating content?

**Same single-user demo profile.** Auth doesn't exist yet. The content studio is for the same anonymous user who creates topics and browses patents. No multi-tenancy, no team sharing.

In practice this means:
- One `user_id` ("anonymous") for all drafts
- No permission checks needed yet
- Draft ownership is implicit

---

## Q2: Surfaces — what content types?

**Primary (V1):**
1. **LinkedIn post draft** — 150-300 word professional post with hook + insight + call-to-action, derived from a patent/trend
2. **Content idea / hook** — short 1-2 sentence hooks suitable for LinkedIn, Twitter, newsletter subject lines

**Secondary (if time permits, or defer to later):**
3. Newsletter blurb — paragraph suitable for a weekly digest
4. Patent one-pager — markdown summary for internal sharing
5. Internal memo — longer form analysis for team consumption

**V1 scope: LinkedIn post draft + content ideas only.** Everything else is stretch.

---

## Q3: Input source — what triggers generation?

Content is generated FROM (in priority order):

1. **A single patent** — "Generate LinkedIn post about this patent." Available on patent detail page (new button/panel alongside Why Now / Opportunity Narrative).
2. **A topic's recent matches** — "Generate content ideas from my AI Agents topic." Available on topic detail page.
3. **A trend** — "Generate LinkedIn post about the rise of quantum computing patents." Available on trend detail (stretch).
4. **A company profile** — "Generate post about Samsung's recent patent activity." (Stretch.)

**V1 scope: (a) single patent generation + (b) topic-based content ideas.**

---

## Q4: Output format — what does the user get?

1. **Markdown text** displayed in-browser, with a "Copy" button that copies raw markdown to clipboard.
2. **No file download** in V1. No PDF. No DOCX. Just markdown in the UI + copy.
3. **Content includes** a mandatory source citation footer (patent number, topic name, generation date) and a caveat ("Generated by AI. Verify before publishing.")

---

## Q5: Storage — persisted or ephemeral?

**Persisted in database.** New table `content_drafts`:
- `id` (UUID)
- `user_id` (string, "anonymous" for now)
- `source_type` (enum: "patent", "topic", "trend", "company")
- `source_id` (UUID of the patent/topic/etc)
- `content_type` (enum: "linkedin_post", "content_idea")
- `content_text` (text — the markdown)
- `status` (enum: "draft", "published")
- `prompt_hash` (for AI caching/artifact tracking)
- `artifact_id` (nullable FK to ai_artifacts — ties into existing AI pipeline)
- `created_at`, `updated_at`

**Also reuse the existing AI artifacts system** for caching: same prompt + same patent = same artifact, no regeneration.

---

## Q6: AI cost model — on-demand or batch?

**Both, but default to on-demand per-click.**

Like Why Now / Opportunity Narrative panels:
- User clicks "Generate LinkedIn Post" on a patent → on-demand API call
- Result is cached via AI artifacts (prompt hash + input hash dedup)
- Same call for same patent returns cached result instantly

**Batch mode** (deferred / stretch):
- Through `/admin/ai-runs`, batch-generate LinkedIn posts for a topic's top 10 matches
- Useful for pre-populating content ideas

Cost discipline:
- Per-generation cost tracked (token usage, model)
- Rate-limited implicitly by caching (can't re-generate same patent without explicit "regenerate" click)
- No auto-batch generation until explicitly triggered

---

## Q7: Acceptance criteria — definition of done for the first feature slice

**First slice: "Generate LinkedIn Post from Patent"**

- [ ] New button/panel on patent detail page: "Generate LinkedIn Post"
- [ ] Click generates a ~150-300 word LinkedIn post in markdown
- [ ] Post includes: engaging hook, key insight from the patent, relevance to industry, call-to-action
- [ ] Post includes source citation footer and AI caveat
- [ ] "Copy" button copies markdown to clipboard
- [ ] Result is cached (re-clicking same patent shows cached result instantly)
- [ ] "Regenerate" button clears cache and regenerates
- [ ] Result saved to `content_drafts` table
- [ ] Duplicate-click protection (uses same `useAsyncAction` pattern)
- [ ] Loading state, empty state, error state handled
- [ ] Backend: new API endpoint `POST /api/v1/content/generate` 
- [ ] Backend: new Celery task or synchronous call (since it's one patent, not batch)
- [ ] Backend: AI artifact created and linked

**Explicitly out of scope for first slice:**
- Topic-based content ideas
- Trend/company-based generation
- Batch generation
- PDF/DOCX export
- Draft management UI (list, edit, delete) — can just show latest on patent detail
- LinkedIn Radar aggregate page

## Open Decisions (for user)

1. **Model choice:** Which LLM for content generation? Options: same as summarization (Sonnet via OpenRouter), or cheaper (Haiku). LinkedIn posts need higher quality than summaries → Sonnet recommended, ~$0.003/post.

2. **UI placement:** New tab on patent detail ("Content"), new panel in Opportunity tab, or standalone button? Tab keeps things organized; panel integrates with existing flow.

3. **Prompt style:** Professional/analytical vs. contrarian/hot-take? Could offer 2-3 "tone" options (analytical, contrarian, curiosity hook) as a dropdown before generating.

4. **Content Studio landing page:** Build now (`/content` showing recent drafts + LinkedIn Radar) or defer until after exports (Phase 5)?
