## 0 — What V3 Is (and Isn't)

V3 is **commercial launch readiness**, not "ship every V2 pillar." The V2
vision lists 7 pillars (Semantic Search → Research Papers → Chatbot →
Knowledge Graph → LLM Wiki → Community → Polish). Shipping all of them is
~12 months of solo work. Revenue target is mid-2027, so V3 picks the 3
pillars that **unblock paid conversion** and defers the other 4 to V4.

**V3 = MVP1.5**: enough magic to charge for, no kitchen sink.

### What's already shipped (do not redo)
- V1 feature set: ingestion, summarization, scoring, expiry, today, search,
  patent detail (with figures), themes, companies, opportunity, trends,
  watchlist, admin, AI runs.
- V2 design overhaul: dark-by-default Palantir aesthetic, 8 primitives,
  Geist typography, theme toggle, responsive.
- Operational floor: CI/CD via GitHub Actions, Sentry skeleton, daily DB
  backups, health endpoint, prod Dockerfile, redis-no-persist, Round 9
  migration applied (alembic_head=0025).
- SaaS scaffolding: Stripe TEST mode wired (4 tiers), magic-link auth,
  email preferences UI, JWT unsubscribe, weekly briefing pipeline, GDPR
  account-delete endpoint.
- Round 7-9 backend: news ingestion (RSS), for-you endpoint with pgvector
  recommendations, weekly briefing fan-out, PatentsView + BigQuery
  backfills, Resend webhooks.

### What V3 will NOT include
Defer to V4: Research Paper ingestion (OpenAlex/arXiv), full Knowledge
Graph visualisation (D3 multi-mode), git-tracked LLM Wiki, Community Layer
(feature requests/upvoting), Slack/Zapier integrations, custom PDF
reports, multi-patent roundups.

These are good. They're not what closes the conversion gap.

## 2 — Phase 1: Semantic Search Foundation (2 weeks)

This is V2 Pillar 1. It's the spine for everything downstream — chatbot,
better recommendations, similar-patents UI. Ship this even if no other V3
phase ships.

### Why first
The for-you endpoint (Round 9) and similar-patents lookups currently rely
on whatever ad-hoc embedding logic was added during V1. Standardising on
**DeepSeek embeddings + pgvector** with a single ingestion path makes all
downstream features (chatbot RAG, paper matching, graph clustering) cheap
to add.

### Scope
- [ ] Pick embedding model + dim. Confirm DeepSeek embeddings is the call
  vs OpenAI ada-002 (cost: DeepSeek ~10x cheaper; quality: comparable for
  English technical text).
- [ ] Migration: ensure `patent_publications.embedding Vector(1536)` is
  indexed with IVFFlat or HNSW. Check what exists.
- [ ] Embedding worker: idempotent task that embeds title + abstract +
  first independent claim. Skip if cached. Batched calls.
- [ ] Backfill all 64K patents (~$50 in DeepSeek API spend at current
  pricing).
- [ ] `GET /api/v1/search` switches from keyword-only to hybrid:
  `0.5 * vector_score + 0.3 * keyword_score + 0.2 * recency_score`.
- [ ] Patent detail page: "Similar patents" panel that's actually
  semantic, not just shared CPC.
- [ ] Search bar: support natural-language queries
  ("hydrogen fuel cell efficiency improvements after 2024").
- [ ] Admin tool: re-embed a single patent on demand.

### Defer
Re-ranking with an LLM (good idea, but expensive per query). Multi-vector
embeddings (per-section). Cross-language search.

### Success criteria
A user can search "battery thermal management for EVs" and get
recognisably relevant results that keyword search misses. Similar-patents
panel surfaces 5 non-obvious neighbours per query.

## 4 — Phase 3: RAG Chatbot MVP (3-4 weeks)

V2 Pillar 3. Most pillar-1 commercial differentiator beyond what
competitors ship.

### Scope (intentionally narrow)
- [ ] SSE streaming endpoint `POST /api/v1/chat/stream`.
- [ ] Retrieval layer: top-K patents + top-K news items by vector
  similarity to query. Cap K=8 to keep context windows sane.
- [ ] Tool layer (3 tools only): `search_patents(query, filters)`,
  `open_patent(doc_id)`, `compare_companies(names)`.
- [ ] Citation enforcement: every claim must cite a patent or news item
  with a clickable link. Decline to answer if no source.
- [ ] Conversation memory: in-Redis, 30-minute TTL, 10-turn cap.
- [ ] UI: a `/chat` page (full-screen) AND a slide-out drawer accessible
  from every patent detail page ("Ask about this patent").
- [ ] Per-user quotas: Free 5/day, Basic 50/day, Lifetime/Enterprise
  unlimited. Quota enforcement aligns to existing tiers.

### Defer
"Build a wiki page from this conversation" (V4). Tool calls that mutate
state (creating watchlists, scheduling alerts). Multi-document
comparative analysis.

### Success criteria
A user can ask "what's happening in solid-state batteries lately" and get
a 2-paragraph summary with 5+ patent citations, all links work, no
hallucinated assignees or dates.

## 5 — Phase 4: Tier Value Differentiation (2 weeks)

Stripe is wired but nothing actually gates behind tiers yet. Users have
no reason to upgrade.

### Scope per tier

companies, daily briefing email.

**Basic ($8/yr)**: 500 patent views/month, unlimited searches, 20 themes,
50 followed companies, CSV export, weekly briefing, 50 chatbot
queries/day.

webhooks (basic) + early-access flag for V4 features.

**Enterprise ($1000/yr)**: All Lifetime + API access + custom themes +
priority support + monthly office-hours call.

### Implementation
- [ ] Quota enforcement middleware: track view counts in Redis with
  per-tier limits, return 429 with upgrade link when exceeded.
- [ ] CSV export endpoint for the 6 main surfaces (`/patents`, `/expiry`,
  `/companies`, `/themes`, `/watchlist`, `/opportunity`). Pro tier only.
- [ ] Upgrade prompt UI: when a Free user hits a quota, show a non-modal
  banner with one-click upgrade.
- [ ] Stripe LIVE products + webhook + dashboard verification.
- [ ] Account/billing page polish — show usage vs quota, days until
  renewal, upgrade/downgrade flow.

### Success criteria
Stripe TEST → LIVE flip done. >10% of registered Free users hit at least
one quota wall within 30 days (signal that the limits matter).

## Honest tradeoffs

1. **V2 Pillars 2 (Research Papers) + 4 (KG) + 5 (Wiki) are exciting**
   but they're V4. Shipping them well takes 3+ months each. Better to
   ship Pillar 1 (Search) and Pillar 3 (Chatbot) deeply than half-ship
   five.

2. **Community Layer is tempting** for the lifetime-tier perception but
   it's a moderation tax. Defer until you have >500 paying users.

3. **Chatbot will dominate AI spend.** Even with DeepSeek, at 50
   queries/day × 100 users × $0.001/query = $5/day = $150/month. Budget
   for it.

4. **Marketing is the bottleneck, not features.** A perfect chatbot
   nobody knows about generates zero revenue. Phase 6 is small in scope
   but disproportionately impactful.

5. **Solo + 12 months to revenue = ship 3-4 things really well**, not
   8 things mediocrely. This roadmap is already aggressive for one
   developer.

# Part II — V4 Vision (Post-Launch Moat Building)

V4 is what makes II8 **defensible**, not just functional. V3 ships a
product worth paying for; V4 ships the things competitors can't quickly
clone. Build only after V3 produces signal that the core thesis works.

## V4 trigger conditions

Do not start V4 work until **all** of these are true:

- V3 Phases 0-6 are deployed
- >100 paying users (any tier)
- MRR >$500 (≈ 60 Basic + 5 Lifetime in first 90 days)
- D30 retention >25% (signed-up users still active on day 30)
- Weekly briefing open rate stabilised >35% over 4 consecutive weeks
- Stripe LIVE mode > 90 days with no chargebacks above 0.5%

If any of these fails, the lesson is "fix V3," not "ship V4." Resist
the urge to add features when the core funnel isn't working.

## V4 Pillar A — Research Paper Intelligence (V2 Vision Pillar 2-3)

**Why this matters**: Patents describe what's protected. Papers describe
what's being explored. Crossing them surfaces "research → patent flow"
6-24 months before competitors notice. This is the moat — nobody else
unifies these corpora at the SME/founder layer.

### Scope
- [ ] Schema: `research_papers`, `paper_authors`, `paper_citations`,
  `paper_topics`, `paper_embeddings`, `paper_patent_links`
- [ ] Ingestion: OpenAlex (primary, free, broad), arXiv (preprints,
  free), Semantic Scholar (citation graph, free with API key). Start
  with OpenAlex only, add others incrementally.
- [ ] Embedding: same DeepSeek pipeline as V3 Phase 1. Title + abstract
  per paper. ~$200 backfill for ~200K relevant papers.
- [ ] Paper-to-patent matching engine: cosine similarity above threshold
  → write `paper_patent_links` row with similarity score.
- [ ] UI: `/papers` index page, `/papers/{doi}` detail page. Each patent
  detail page gets a "Research foundation" panel showing top-5 related
  papers. Each paper detail page shows related patents.
- [ ] Trend layer: when a CPC area sees both filing spike AND paper
  publishing spike, flag as "research-driven trend" (high signal).
- [ ] Author/inventor overlap: when paper author later becomes patent
  inventor, surface that on both surfaces.

### Time estimate
6-8 weeks. Largest chunk is data engineering (OpenAlex has 250M+ works;
need careful filtering by topic/year).

### Cost
~$200 one-time embedding backfill, ~$30/month ongoing for new paper
inflow.

### Open questions
- Filter strategy: how to scope from 250M OpenAlex works to 200K
  "relevant to patent themes." Topic-based? CPC-aligned? Citation-network?
- Update cadence: real-time webhook vs daily batch?
- License: OpenAlex is CC0, arXiv is mixed — clear policy needed for
  showing full abstracts vs preview.

## V4 Pillar B — Knowledge Graph (V2 Vision Pillar 4)

**Why this matters**: Patent space is fundamentally relational. Static
tables hide the network. A graph lets users see "this assignee files
in CPCs X, Y, Z; X is filed by 4 competitors; Y has one expiring patent
that links to a 2024 paper from a different inventor." That's the
"holy crap" moment.

### Approach
**Query-driven, NOT pre-rendered.** Generating a 64K-node graph
crashes browsers. Each user query produces a focused 50-200 node
subgraph relevant to their question.

### Scope
- [ ] D3.js force-directed layout in a dedicated `/explore` route
- [ ] Modes:
  - Company landscape (focus assignee → competitor assignees + shared
    CPCs)
  - Technology cluster (focus CPC → patents + assignees + papers)
  - Citation network (focus patent → cited + citing + family)
  - Inventor network (focus inventor → patents + co-inventors +
    affiliated companies)
  - Expiring opportunity map (expiring patents + assignees + downstream
    industries)
  - Whitespace map (CPC areas with low filing density + adjacent
    growing CPCs)
- [ ] Progressive expansion: click a node → API call → 20 more nodes
  appear. Cap at 500 nodes per session.
- [ ] Chatbot integration: "show me the graph of solid-state battery
  inventors" → chatbot calls `expand_graph` tool → graph renders.
- [ ] Export: PNG snapshot of current graph state (Lifetime+).

### Time estimate
4-6 weeks. D3 is finicky; performance tuning takes time.

### Cost
Negligible runtime cost. One-time engineering.

### Open questions
- 2D vs 3D? Recommend 2D for V4; 3D is a perception-of-magic upgrade
  for V5.
- Server-side rendering vs client-side? Recommend client-side D3 with
  pre-computed positions from the server.
- Saved graph states (let users bookmark a configuration)? Yes for
  Lifetime+.

## V4 Pillar C — LLM Wiki (V2 Vision Pillar 5)

**Why this matters**: Every AI-generated narrative (why-now,
opportunity, trend) is currently siloed. A Wiki turns one-off
summaries into a navigable, accumulating knowledge base. Plus
SEO — Google indexes wiki pages, drives organic traffic.

### Architecture
- Git-tracked markdown in a dedicated repo branch or sub-repo
- LLM builds + maintains; humans can edit (audit trail via git)
- Obsidian-compatible (`[[wikilinks]]`, frontmatter YAML)
- Each page has: title, content, last_updated, sources (citations to
  patents/papers/news), confidence

### Page types
- Company pages: history, top tech areas, recent filings, key
  inventors, competitive landscape
- Technology pages: CPC-area summary, key players, recent advances,
  expiring opportunities, related research
- Research frontier pages: hot CPC + hot paper area together
- Opportunity pages: specific expiring patents with full context
- Weekly briefings (archived as wiki pages)

### Scope
- [ ] Wiki repo + sync service (write/read via FastAPI)
- [ ] Page generation triggered by:
  - User clicks "Create wiki page from this analysis" in chatbot
  - Scheduled job (e.g., regenerate company pages weekly)
  - Editorial calendar (one curated frontier page per week)
- [ ] `/wiki` index + `/wiki/{slug}` detail routes
- [ ] Search within wiki (already covered by V3 semantic search if
  embedded)
- [ ] Public wiki pages (with `noindex` initially, opt-in to index)

### Time estimate
4-6 weeks.

### Cost
~$0.05/page generation × ~10K pages = $500 one-time, ~$50/month
ongoing.

### Open questions
- Public or gated? Recommend public read, gated edit. SEO wins are
  enormous if public.
- LLM editing vs append-only? Recommend append-only initially (LLM
  writes, humans cannot delete; humans can append corrections). Avoids
  trust/vandalism issues.
- Versioning: every regeneration is a new git commit, but show diff?
  Yes for transparency.

## V4 Pillar D — Community Layer (V2 Vision Pillar 6)

**Why this matters**: Lifetime tier feels like a club. Users with
skin-in-the-game shape the product. Network effects start when users
talk to each other.

### Scope
- [ ] Feature requests board:
  - Lifetime users: 1 submission + 1 upvote per calendar month
  - Free/Basic: read-only access
  - Enterprise: unlimited submissions/votes
  - Status workflow: open → in-progress → done / declined (with reason)
- [ ] Public topic boards: comment threads on `/t/{slug}` and
  `/c/{name}` pages. Lifetime+ can post.
- [ ] Saved research boards (Pinterest-like): users curate patents +
  papers + insights into named boards. Public-by-default with private
  option.
- [ ] Watchlist alerts already shipped in V3 Phase 5; this phase adds
  collaborative watchlists (Lifetime+ can invite others to view a
  watchlist).
- [ ] Weekly digest of "what users are watching" (anonymized).

### Time estimate
3-4 weeks (but the moderation overhead is the real cost).

### Cost
Negligible compute. **Moderation tax** is the killer — budget 1-2
hours/week of Andy's time for the first 6 months.

### Open questions
- Public profiles for users? Recommend opt-in. Default
  anonymous-but-consistent (e.g., "andy-the-engineer").
- Comment moderation: automated (OpenAI Moderation API) + manual
  review queue. Lifetime users self-police via report button.
- Spam: rate limits + first-post-requires-review for new accounts.

## V4 Side Quests (smaller, opportunistic)

These don't deserve full pillar status but should be tracked:

### Slack / Zapier integrations
- Slack: outbound webhooks for alerts. ~3 days work.
- Zapier: requires public stable API (already partial in V3). ~1 week.
- Prereq: V3 Phase 5 alerts shipped + stable.

### Custom PDF reports
- "Generate a report on solid-state batteries" → chatbot composes →
  PDF generated server-side → email or download.
- Lifetime/Enterprise only.
- ~2 weeks.

### Multi-patent content
- LinkedIn 4.1 already ships single-patent posts. Extend to:
  - Roundup posts (3-5 related patents in one piece)
  - X/Twitter thread generator
  - Newsletter paragraph generator
  - Founder idea memo generator
  - Investor angle memo generator
- ~1 week per format. Cherry-pick based on user requests.

### Mobile shell
- Not a native app — a PWA wrapper around existing responsive
  frontend, with push notification support for alerts.
- ~2 weeks.
- Prereq: alerts actually working at scale (V3 Phase 5).

### Cross-language search
- V3 ships English-only. V4 add Japanese, German, Chinese, Korean
  patent text via translation layer (DeepSeek can do this).
- ~3 weeks.
- Demand-driven: only ship if multiple paying users request it.

### LLM re-ranking
- V3 search is hybrid (vector + keyword + recency). V4 adds an LLM
  re-rank step over top-50 candidates.
- Expensive per query; budget ~$0.005/search.
- Ship only for Pro+ tiers.

### Multi-vector embeddings
- V3 embeds title+abstract+claim as one vector. V4 indexes per-section
  (separate vectors for title, abstract, claims, description) enabling
  "find patents with similar claims but different applications."
- ~2 weeks. Real intellectual juice for power users.
